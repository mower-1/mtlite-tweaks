# Mt论坛Lite 重制版 1.7.5 修改总结

## 0. 一句话结论

在原版基础上新增两个独立模块：`libs/tiezi_plus.lua`（帖子页）与 `libs/pm_plus.lua`（私信页），
都是「Lua 原生层 + 注入到网页的 JS」，实现四块功能：
**回复可见自动回复**、**评论屏蔽**、**自动上下页（重写）**、**私信限速自动重发**，并在设置页加了 7 个入口。
原生层只负责"开关 / 配置 / 弹窗 / 收消息"，真正的页面处理全部在注入的 JS 里，所以**换版本时主要改的是选择器，不是逻辑**。

## 3. 四个功能的实现要点

### 3.1 回复可见自动回复

**识别（三重条件取交集，宁漏勿错）**

真实页面结构（comiis 模板）：

```html
<div class="comiis_quote bg_h f_c">昵称，如果您要查看本帖隐藏内容请<a href="...action=reply...">回复</a></div>
```

判定顺序（`findNotice()`）：

1. 在 `.comiis_quote / .showhide / [class*="showhide"] / .comiis_hidebox` 里找；
2. 文本 ≤ 220 字，且含 `隐藏|回复可见|回复后可见|回复才能`；
3. 且 **类名带 `showhide`** 或 **块内有 `action=reply` 链接** → 命中；
4. 兜底：只在**楼主帖正文**里找，且正文存在回复链接，子节点文本 ≤120 字并匹配
   `查看本帖隐藏|隐藏内容.{0,6}回复|回复.{0,6}(可见|查看|浏览)`。

> 早期只判断"短文本里同时出现 回复/回帖 和 可见/隐藏"，结果评论里一句"看看隐藏"就误报。第 3 条的"必须存在回复链接"是修掉误报的关键。

**询问框**

- 只读一行「回复内容：看看隐藏」+ 一行「请到 设置 → Js → 自动回复内容 修改」，按钮：自动回复 / 取消。
- 输入框已按要求移除，回复内容只能在设置页改。

**自动回复（`doReply`）**

```
填 textarea#needmessage（或 textarea[name=message]）并派发 input/change
→ 优先 window.fastpostvalidate(form)（走论坛自身校验，兼容验证码、发帖间隔）
→ 失败则点 #fastpostsubmit
→ 再失败则 HTMLFormElement.prototype.submit.call(form)
→ 成功后 alert('__MLITE_REPLY_SUBMITTED__')，3.5 秒后 location.reload()
```

**省电**

- 只在帖子页注入；`MutationObserver` + 500ms 轮询**最多 20 次（10 秒）**；
- `document.hidden` 时跳过且不消耗次数；命中或取消立即 `disconnect + clearInterval`；
- 原生层用 `本地已提示tid` 去重，同一帖子只问一次；回复后仍检测到提示会提示"可能未成功，请手动回复"，不会无限弹。

### 3.2 评论屏蔽

**判定顺序（`blockReason`，命中即返回）**

1. 去掉所有空白后为空 → 不屏蔽；
2. **长度 > 10 → 一律不屏蔽**（用户定的阈值，水贴都是短句）；
3. 整条只由可打印 ASCII 组成（`/^[\x20-\x7E]+$/`）且**不含 `.`** → 屏蔽（`. ` 可能是链接/版本号）；
4. 命中屏蔽词 → 屏蔽；屏蔽词按 **`new RegExp(词,'i')`** 匹配，编译失败自动退化为 `indexOf`。
   正则不带锚点 = **包含匹配**。

**豁免**

- 楼主帖不屏蔽：`isOP()` 认 `.comiis_postli_topv1 / .comiis_pltit`；`#post_new`（回复编辑器）也排除。
- **回复别人的楼层不屏蔽**：`isReplyToOther()` —— 楼层里有 `.comiis_quote` 且内容不是"查看本帖隐藏"提示。
  取正文用 `bodyText()`，会把引用块文本剔除，避免引用原话把长度撑过 10 字导致漏屏蔽。

**消失方式**

```css
.comiis_postli[data-mlite-blocked]{display:none !important;}
```

整层 `display:none`，下方内容自然上移，不留空白。同时打 `data-mlite-blocked="命中原因"`（超 20 字截断）便于排查。

**持续生效**

`MutationObserver` 监听 `body` 的 `childList`（150ms 防抖合并），所以"自动上下页"拼接进来的新楼层同样会被扫到；楼层新加了 `data-mlite-scanned` 标记避免重复判定。

**屏蔽词解析（Lua 侧 `屏蔽词列表()`）**

- 按行拆；空行跳过；
- **一行里只要含 `| ( ) [ ] { } ^ $ . * + ? \` 就整行当一条正则**（否则 `{2,3}` 会被逗号拆坏）；
- 纯词行才按 `， , ； ; 、` 拆成多个词（兼容老数据"谢谢，感谢"）。

### 3.3 自动上下页（完全重写）

原版逻辑被整体替换（`pages/tiezi/main.lua` 里原来的 `automatic_page_down()` 调用已注释，改由注入脚本接管）。

**参数**

| 参数 | 值 | 位置 |
|---|---|---|
| 并行页数 | 1~4，默认 2 | 设置页 → `CFG.parallel` |
| 预加载阈值 | 2 屏 | `CFG.preload`（硬编码 2） |
| fetch 超时 | 8 秒 | L538 |
| 隐藏 iframe 兜底超时 | 12 秒 | L558 |
| 单页失败重试 | 1 轮 | `failCount[p] <= 1` |
| 空页容忍 | 连续 2 页 | `emptyStreak >= 2` |
| 风控后自动复活 | 2 次，间隔 >3s | `revives < 2` |
| 轮询兜底 | 1 秒 | `setInterval(checkFill, 1000)` |

**"是否到底"的判断（核心坑）**

不碰 `documentElement.scrollTop`（Fusion App 的 WebView 里常读到 0），改为：
取**最后一个可见楼层**的 `getBoundingClientRect().bottom`，距视口底部不足 `preload` 屏就算接近底部。
楼层全被屏蔽时退回整体 `scrollHeight - scrollTop - innerHeight` 判断。

三路触发兜底：`document` 捕获阶段监听 scroll（内层滚动容器也能收到）+ 哨兵元素 `IntersectionObserver`（rootMargin 提前 2 屏）+ 1 秒轮询（`document.hidden` 跳过，`done` 后自动 `clearInterval`）。

**加载与拼接**

- 抓取：`fetch` + `DOMParser`（带 `Accept`、`referrer`，减少被判爬虫）→ 拿不到 `.comiis_postlist` 就降级隐藏 iframe（允许 3 次 onload 过 WAF 挑战页）。
- 顺序：按页码 `flush`，回包乱序不会错位；并行预取最多 `parallel` 页。
- 去重：按 `.comiis_postli` 的 `pid`（`seen` 集合）。
- 插入位置：`#post_new`（回复编辑器）之前。
- 提示条 `#mlite-tail-tip`：加载中「正在加载第 N 页…」；风控失败变蓝可点「后续楼层加载失败，点此重试」；末页显示「当前已是最后一页」2.6 秒后消失。

**末页 vs 失败（必须分清）**

`pagerOf(doc)` 只看 `.comiis_page / .comiis_multi_box`：

| 情况 | 判定 |
|---|---|
| 有"下一页"且有 href | `hasNext:true` |
| 有"下一页"但无 href（末页是 `<a class="bg_f b_ok f_d">下一页</a>`） | `hasNext:false` = 末页 |
| 没有"下一页"文字（图标按钮） | 看 `#dumppage` 的 option：`maxP > cur` 则有页，否则末页 |
| 连分页区都没有 | `ok:false`，交给 `nextLinkOf` 兜底；没有链接就当单页帖 |

`start()` 里：首屏即末页 → **一次请求都不发**，直接 `done`。

**页码同步（`syncDump`）**

真实分页区里"第 1 页"是 `#select_a` 的**文本节点**，`#dumppage` 是 `opacity:0` 的透明 select。所以四处一起改：
`select.value` → 各 `option.selected` → `#select_a` 文本节点（正则替换「第 N 页」）→ 上一页/下一页链接的 href（`withPage(href, p±1)`）。

### 3.4 私信：固定窗口倒计时 + 待发队列 + 页面内卡片

> 这一节前后改了四轮，前三轮的结论都已作废，写在这里主要是**别再走回头路**：
> 1. 按「整页跳转 + 弹窗」实现 —— 全错，发送根本不跳页；
> 2. 按抓包改成 XHR + 冷却，但把 15 秒当固定值 —— 没被限速也弹倒计时；
> 3. 改成「先验证、再倒计时」+ 服务端秒数/实测校准 + 原生 DecorView 悬浮窗 —— 真机上悬浮窗**一次都没出现过**；
> 4. **现在这版**：服务端不参与算时间，固定窗口 + 网页内卡片渲染。

**真实链路（HAR 实测）**

```text
POST home.php?mod=spacecp&ac=pm&op=send&pmid=251249&daterange=2&pmsubmit=yes&mobile=2
     Content-Type: multipart/form-data
     formhash / touid / message / pmsubmit

200 → 插件 forum_rate_limit 处理，返回 JSON（字段疑似 {forum_rate_limit, ok, message, redirect}）
```

三条必须记住的事实：

1. 发送是插件用 **XHR** 发的，**不跳页**；失败时在页面正中插 `#frl-notice`（约 4 秒消失），文案含「太快」。
2. **服务端不告诉"还剩多少秒"**。抓包里响应体是 `application/octet-stream` + zstd，**从来没抓到过可读的字段**，
   所以任何"按服务端秒数校准"的方案都不可靠 —— 剩余时间只能自己记。
3. 发送成功后，页面**不会**自己把新消息画出来，必须手动刷新才看得到（**原版就有这个问题**，不是这段代码引入的）。

**计时模型（固定窗口，不校准、不翻倍）**

- 每成功发出一条 → `last_ok = now`；
- 可再次发送的时刻 = `last_ok + 窗口秒数`（设置项，默认 16）；
- 窗口内再点发送 → 拦下来入队，倒计时 = **真实剩余**：
  成功后在**第 3 秒**再发 → 显示 13；在**第 10 秒**再发 → 显示 6（16 秒窗口）；
- 到点自动发出；**仍被拒 → 弹窗说明 + 把这条标成「被拒」，不再翻倍重试**，
  卡片里显示「被拒 · 点此重发」，由用户决定；
- 倒计时结束后**手动**发送被拒（说明网站真实限制比设置长）→ 底部提示一次，
  并按设定秒数重新排一次队（只排一次，避免死循环）。

**数据结构（应用存储 `私信发送状态`）**

```json
{ "last_ok": 1792243015000,
  "seq": 2,
  "q": [ { "id": 1, "t": "文本", "u": "会话地址", "d": 1792243030000, "sent": 0, "fail": 0 } ] }
```

- `d` = 计划发送时间（毫秒时间戳），由 `重排队列()` 按 `last_ok + n×窗口` 算；
- `sent` = 正在发送的时间戳（非 0 表示已点过发送，等结果）；
- `fail` = 被服务端拒绝过，等用户手动「重发」；
- `win` 字段**不再持久化**，直接用设置里的秒数。

**点击拦截（窗口内不让请求发出去）**

```js
window.addEventListener('click', function (ev) {   // window 捕获，早于插件在 form 上的冒泡监听
  …
  var left = leftMs();
  if (left <= 0) { sendingText = text; return; }   // 窗口外：照常发
  ev.preventDefault(); ev.stopPropagation(); ev.stopImmediatePropagation();
  report('__MLITE_PM_Q|' + JSON.stringify({ t: text, u: location.href }));
  setVal(el, '');
  toast('还要等 ' + Math.ceil(left / 1000) + ' 秒，这条已加入队列');
}, true);
```

回车提交另有一道 `submit` 捕获监听，走同样的分支。

**读发送结果（容错优先）**

```js
function onResult(raw) {
  var r = null; try { r = JSON.parse(raw); } catch (e) {}
  var msg  = r ? String(r.message || '') : raw;
  var 限速 = /太快|稍后再|发送间隔|间隔/i.test(msg);
  var 成功 = 限速 ? false : (r ? (r.ok !== false) : true);   // 非 JSON 的整页响应也算成功
  …

```

> 上一版只认 `r.ok === true`，结果**成功也被当成"未知结果"**，刷新逻辑根本没跑起来 —— 这是「发完还是不显示」的第一层原因。

**界面：网页内卡片 `#mlite-pm-card`**

原生 DecorView 悬浮窗在这个工程里挂不上去（第 3 轮的失败），所以改成在网页里画：

```text
┌─────────────────────────────┐
│ ① 12 秒后自动发送 · 内容…  取消 │
└─────────────────────────────┘
```

- `position:fixed; left:10px; bottom:118px; z-index:2147483000`，深色圆角，12.5px；
- 没有排队消息时只显示一行「距可再次发送 12 秒」，归零自动消失；
- 状态文字：`N 秒后自动发送` / `正在发送…` / `被拒 · 点此重发`；
- 每秒重绘一次（`setInterval(tick, 600)`），HTML 没变就不动 DOM；
- 点击「取消 / 重发」用 `data-c` / `data-r` 属性 + 卡片内事件委托，不重建监听。

**消息通道（双通道，互为备份）**

| 通道 | 实现 | 说明 |
|---|---|---|
| 主 | `alert('__MLITE_PM_*')` | 走 `单页文件上传影视解决(...)` 第 5 个参数（网页提示框），Lua 里 `result.cancel()` 不弹给用户 |
| 备 | `window.__mlitePmOut` 数组 | JS 把同一条消息也塞进数组，原生每 700ms `加载Js(...回调)` 取回并清空 |

- 两条都到也没关系：原生侧「1.5 秒内相同报文只处理一次」去重；
- 轮询用 `私信延时()`（先试框架 `task`，失败退 `Handler(Looper.getMainLooper()).postDelayed`）；
- 连续 10 分钟没有任何消息就停轮询（每次收到消息重置计数），别一直后台跑。

**消息协议**

| 消息 | 含义 | 原生动作 |
|---|---|---|
| `__MLITE_PM_H` | 脚本注入成功的握手 | 底部 toast 一次「私信自动重发已启用」（每进程一次，用来判断注入是否生效） |
| `__MLITE_PM_OK` | 发送成功 | `last_ok = now` → 重排队列 |
| `__MLITE_PM_L\|{id}` | 到点自动重发仍被拒 | 标 `fail` + `AlertDialog` 说明（不翻倍） |
| `__MLITE_PM_L\|{t,u}` | 手动发被拒 | `last_ok = now` + 入队一次 + 底部提示 |
| `__MLITE_PM_Q\|{t,u}` | 窗口内被拦下的点击 | 入队 |
| `__MLITE_PM_T\|id` | 开始自动发送 | 记 `sent` |
| `__MLITE_PM_D\|id` | 自动发送成功 | 出队 + `last_ok = now` |
| `__MLITE_PM_N\|id` | 点了发送但按钮点不动 | 标 `fail`，交回用户 |
| `__MLITE_PM_X\|id` | 20 秒没回音 | 标 `fail`，避免一直挂着 |
| `__MLITE_PM_C\|id` | 用户点「取消」 | 出队 |
| `__MLITE_PM_R\|id` | 用户点「重发」 | 清 `fail`、`d = now`，下一轮 tick 就发 |
| `__MLITE_PM_F\|{m}` | 其它失败原因 | `print` 出来 |

**发送后自动刷新列表（补原版的坑）**

```js
afterSendRefresh(text)            // 成功后 450ms 触发
  └─ GET 当前会话 URL + "_mliter=<ts>"   // 加参数破 WebView 缓存
     └─ DOMParser 解析出 #comiis_pm_list
        └─ 替换现页 innerHTML + 滚到底
           └─ 用刚发的文本做内容校验：没有 → 再抓一次 → 仍没有 → location.reload()
```

- 只换消息列表，**不动 `#pmform`**，所以输入框和草稿都不受影响；
- `#comiis_pm_list` 在当前页找不到时直接 `location.reload()`（不静默跳过）；
- 整页 reload 前把草稿写进 `sessionStorage`（带 `touid` 校验），
  reload 后按 `mlite_pm_after` 标记把草稿填回 + 滚到最新一条。

**自动发送不吃草稿**

自动补发必须临时把队列内容填进输入框再点发送，所以在填之前：

```js
pendingDraft = 当前框内容（非空且不等于要发的那条时才记）
pendingSent  = 要发的文本
```

发送结果回来后 260ms 调 `restoreDraftAfterSend()`：**框里是空 或 还是刚发的那句**才把草稿放回去，
用户中途已经打了别的内容就不动。

**防呆**

- 同一内容正在排队时不重复入队；
- 排队超过 1 小时的消息在注入时清掉；
- 别的会话（`touid` 不同）的队列项不会在本页发；
- `autoId` 20 秒没结果就清掉并标 `fail`，不会无限重试；
- 刷新列表有 `pmRefreshing` 锁 + 9 秒兜底解锁，避免重入。

**调试接口**：页面控制台里 `__mlitePm.state()` 看 `{win, last, left, my, q}`；
`__mlitePm.tick()` 可手动催一次自动发送。

### 3.5 电脑版网页（右上角菜单）

**目标**：任意页面 → 右上角 ⋮ →「电脑版网页」，用电脑版界面看当前这一页。

**为什么不是「就地换 UA 再重载」**

- 本工程有 **46 处** URL 规则依赖 `mobile=2`（`url:match'...&mobile=2'` 用来判断新发帖、板块跳转、短信绑定等），
  就地改写地址会把现有路由打断；
- 换 UA 重载还会让帖子页/私信页的注入脚本跑在桌面 DOM 上（选择器全不匹配）。

**做法**：借用现成的「浏览页PC」`pages/liulanyepc`（它的 UA 就是 `拓展功能 → 电脑UA`），把当前地址传过去。

```lua
-- libs/gongyong.lua
function 电脑版网址(链接)      -- mobile=2  -> mobile=no
function 手机版网址(链接)      -- mobile=no -> mobile=2
function 打开电脑版网页()
  local u = 获取网址() or ""
  if u == "" then u = "https://bbs.binmt.cc/" end
  if u:find("^file://") then print("本地页面没有电脑版") return end
  进子页面("liulanyepc",{电脑版网址(u)})
end
```

菜单项加在 7 个页面的 `右上角按钮(0,0).onClick` 里——`主菜单.add("电脑版网页")` 放在「退出页面」之前，
`switch item.title` 里加 `case "电脑版网页" 打开电脑版网页()`：

`bankuai / sousuo / qiandao / tiezi / yonghu / zhuye / zhuye/jinghua`

**关键：`mobile=2` 必须换掉**

Discuz 用 `mobile` 参数 + UA 共同决定模板；只换桌面 UA 时，带 `mobile=2` 的地址仍然是触屏版。
所以统一改成 `mobile=no`（Discuz 标准的「强制 PC」写法）；没有该参数的地址（如 `thread-156697-1-1.html`）
保持原样，靠 UA 决定，别多此一举加参数。

**电脑版页面的渲染**

`liulanyepc` / `liulanyeqp` 各加两行 WebSettings：

```lua
设置.setUseWideViewPort(true)
设置.setLoadWithOverviewMode(true)
```

桌面模板没有 viewport meta，不开这两项只能看到页面左半边；自带 viewport 的网页（蓝奏云等）不受影响。

**回到手机版（第三版：直接关掉电脑版页面）**

第二版是「在同一个 webview 里套手机 UA 后重载」。真机上确实能切回来了，但体验上还有两个毛病：

1. 切一次等于**重新加载一遍**，看起来像又跳了一个新页面；再切一次又是一遍，返回栈也跟着变长；
2. 更要紧的是，重载出来的是**一个没有导航栏的页面**——`liulanyepc` 是独立子页面，没有首页那排
   「首页 / 社区 / 导读 / 我的」指示器，用户看到的就是「手机版，但导航栏没了」。

第三版把「切回手机版」改成**关掉电脑版页面**：

```lua
-- liulanyepc / liulanyeqp
入口网址 = tostring(传递数据 or "")     -- 进来时的那一页
function 回到手机版()
  重置手机版Cookie()
  local 当前 = 获取网址() or ""
  -- ① 没翻页：直接关掉本页 → 回到原来的页面（原页面自带导航栏，且不会重新加载）
  if 同一网页(当前, 入口网址) then 退子页面() return end
  -- ② 翻到别的页面了：交给 App 自己的页面打开
  if 用手机版页面打开(手机版网址(当前)) then return end
  -- ③ 实在接不了：用手机版浏览页打开
  进子页面("liulanye",{手机版网址(当前)})
  退出页面()
end
```

- `同一网页()` 比较前会去掉 `mobile=` 参数和 `#锚点`，所以 `...&mobile=no` 与 `...&mobile=2` 算同一页；
- 全屏页 `liulanyeqp` 用简化版：同一页就 `退子页面()`，翻过页了才在本页切回手机版（全屏页本来就没有导航栏）；
- 「用手机版页面打开」是一张 URL → 页面的分发表：
  `thread-x-y-z.html` / `mod=viewthread` → `tiezi`；`forum-x-y.html` / `mod=forumdisplay` → `bankuai`；
  `mod=space&uid=` / `mod=space&do=profile` → `yonghu`；`k_misign` → `qiandao`；`mod=logging` → `denglu`。
- 关掉电脑版页面前仍会调一次 `重置手机版Cookie()`，免得下次进手机版页面时服务端又按 cookie 给电脑模板。

**进电脑版时先把地址纠一次（原版就有的问题）**

首页那栏的地址是 `forum.php?mod=guide&view=hot&mobile=2`（导读-热帖），社区那栏是 `forum.php?forumlist=1`。
这两个地址在电脑版下都不是「论坛首页」，直接打开会落到导读页 / 版块列表页（用桌面浏览器打开也一样）。
所以在 `打开电脑版网页()` 里先纠一次：

```lua
local 主机 = u:match("^(https?://[^/]+)") or "https://bbs.binmt.cc"
if u:find("view=hot") or u:find("forumlist=1") then
  u = 主机 .. "/forum.php"
end
```

- 首页 → `https://bbs.binmt.cc/forum.php`；
- 社区 → 同样进论坛首页（论坛没有「社区」对应的电脑版页面，这样最贴近预期）；
- 导读（`view=newthread`）保留电脑版的导读页；
- 其余地址（帖子、板块、用户页、精华…）原样做 `mobile=2 → mobile=no`。

`zhuye` 的菜单还会先用 `this.uiManager.viewPager.getCurrentItem()` 读当前在第几栏：
0/1（首页/社区）→ 论坛首页，2（导读）→ 电脑版导读，其它按当前地址。
索引读不到也没关系，上面的 URL 纠错仍能兜住首页与社区。

**注意**

- 电脑版页面是独立子页面，返回即回到原页面，不改动 App 自己的路由状态；
- 「手机模式」在没翻页时等价于「返回」：不重新加载，回到带导航栏的原页面；
- 电脑版下帖子页的「回复可见自动回复 / 评论屏蔽」不会生效（选择器是手机模板的），这是预期行为。

### 3.6 评论「回复」弹层里的快捷菜单

**现象**：帖子底部快速回复框（`#fastpostform`）一获得焦点，底部会弹出原生 Chip 快捷菜单（加粗/斜体/下划线…）；
点某楼的「回复」弹出的小窗（`#ntcmsg_popmenu`）里**没有**这排按钮。

**原因：页面上有两个同 id 的 `textarea`**

```html
<!-- 底部快速回复 -->
<form id="fastpostform"><textarea id="needmessage" name="message"></textarea></form>

<!-- 点某楼「回复」的弹层（form 在弹层里，id 一样） -->
<div id="ntcmsg_popmenu" class="dialogbox comiis_textarea_box">
  <form id="postforms"><textarea id="needmessage" name="message"></textarea></form>
</div>
```

1. 原生菜单栏的显示是由网页里的 `alert("点击了回复")` 触发的，而这个 alert 挂在
   `document.getElementById("needmessage").onclick` 上（`control.json` 注入），
   `getElementById` 只会返回**第一个**，也就是底部那个 —— 弹层里的框永远不触发；
2. 就算把菜单栏叫出来，快捷菜单里的 JS 全部是 `changeText("needmessage", …)` /
   `insertText(document.getElementById('needmessage'), …)`，仍然会插到**底部那个框**里。

**做法（`tiezi_plus.lua` 注入脚本新增一段）**

```js
function popTextarea() {                 /* 弹层里那个可见的 textarea */
  var p = popupBox();                    /* #ntcmsg_popmenu，找不到就按 .comiis_textarea_box */
  if (visible(p)) return p.querySelector('textarea[name="message"]');
  /* 兜底：除底部快速回复之外，页面里还可见的那个 */
  ...
}
function sync() {
  var on = popTextarea() ? 1 : 0;
  patch(on);                             /* 弹层开着就把 getElementById('needmessage') 临时指过去 */
  var want = (on || fastOpen()) ? 1 : 0;
  if (want === barOn) return;
  barOn = want;
  alert(want ? '点击了回复' : '关闭了回复');   /* 复用原有的显示/隐藏通道 */
}
```

**为什么不用轮询（第二版改成事件驱动）**

第一版用 `setInterval(sync, 500)`。问题是 `popTextarea()` 里要读 `offsetWidth/offsetHeight` 判断可见性，
**每次读都会强制浏览器做一次同步布局**；500ms 一次，滚动长帖、图片陆续加载时等于一直被打断。

改成「有动作才查」之后，页面空闲时**一点开销都没有**：

| 触发 | 时机 | 谁负责 |
|---|---|---|
| 回复请求返回 | 点「回复」后那次 XHR 的 `loadend` | `kick(3)`：60/260/460ms 各查一次，够弹层插进 DOM |
| 点击 | 捕获阶段所有点击 | 打开弹层、点「取消」、点遮罩关闭 |
| 输入框聚焦 | `focusin` | 直接点弹层里的输入框 |
| 弹层显示/隐藏 | `MutationObserver` 只盯弹层节点的 `style`/`class`，150ms 节流 | 网站自己 show/hide |
| 页面空闲 | 什么都不做 | 没有 `setInterval` |

请求的识别条件（抓包确认）：

```
GET /forum.php?mod=post&action=reply&fid=42&tid=174956&repquote=11983063&page=1&inajax=1
→ action=reply 且（mod=post 或 inajax）
```

同时钩了 `XMLHttpRequest` 和 `fetch` 两条路；别的请求（导读、帖子列表等）不会触发任何检查。

- **显示/隐藏**复用原来的 `点击了回复` / `关闭了回复` 消息（`tiezi/main.lua` 里已经会据此显隐 `bottom`），
  不新增原生接口；
- **输入目标**：弹层开着时给 `document.getElementById` 打一个临时补丁，`id === 'needmessage'`
  就返回弹层里的 textarea；弹层关掉立刻 `delete` 掉补丁恢复原状。这样 22 个快捷菜单项一行都不用改；
- **底部框开着时**（`.comiis_fastpostbox` 的 `display` 不是 none）即使弹层关掉也**不收起**菜单栏，
  避免把用户本来打开的回复框菜单一起收走；
- 判定弹层「开着」用 `offsetWidth/offsetHeight + computedStyle`，因为模板靠 `display:none` 收起；
- 弹层 id 万一变了还有兜底：找页面上除底部回复框之外**可见的** `textarea[name="message"]`。

**注意**：快捷菜单只能改 textarea 的 `value`，Discuz 提交时读的就是它，不受影响；
但菜单里的「表情/图片」是网站自己的按钮，弹层里没有，这个没动。

### 3.7 侧边栏「请登录 / 登录失效」（原版 bug）

**现象**：已经登录了，进软件左侧栏还是「请点击刷新 / 请登录」；点一下刷新又弹「登陆失效，请重新登录」；
更怪的是登录页刚提示「登录成功」，紧接着就弹这个。

**三个原因叠在一起**

1. **判断登录用的是装饰性 cookie**：旧代码要求 cookie 里能匹配到
   `cQWy_xxx_comiis_homestyleid_u…=…%2A…`（模板的侧边栏壁纸），取不到就直接 `print2("登陆失效，请重新登录")`
   并把 `登录参数` 清空 —— 这个 cookie 跟登录态没有关系，没有它不代表没登录。
2. **昵称靠整段正则**：`'<p><span class="…">…</span></p>.+<p class="f13…">…'`。
   当前模板里两个 `<p>` 之间是换行，而 Lua 的 `.` **不匹配换行** → 匹配失败。
3. **每次首页加载都重算一次**：`页面事件处理(1, …)` 的加载完成回调里会调 `使用登录参数登录()`，
   所以登录成功、App 重启回首页、首页一加载完就立刻又判一次 → 失败 → 弹「登录失效」。

**改法**

```lua
function Cookie已登录(ck)          -- 只认 Discuz 的登录 cookie，deleted 视为登出
  local 值 = ck:match("[%w_]+_auth=([^;]*)")
  return 值 ~= nil and 值:gsub("%s","") ~= "" and 值:gsub("%s","") ~= "deleted"
end

function 解析侧边栏(html)          -- 先定位 .sidenv_user 块，再按 class 单点取，不跨行
  块 = html:match('class="sidenv_user"(.-)</a>') or html:match('class="sidenv_edit">(.-)class="sidenv_li">')
  名字 = 块:match('class="user_tit[^"]*"%s*>%s*(.-)%s*</span>')
  等级 = 块:match('class="user_lev[^"]*"%s*>%s*(.-)%s*</span>')
  头像 = 块:match('<img[^>]-src="(.-)"')
  头衔, 积分 = 块:match('<p class="f13[^"]*">%s*<span[^>]*>%s*(.-)%s*</span>%s*<span[^>]*>%s*(.-)%s*</span>')
end
```

处理结果分三档，只有第三档才清登录态：

| 情况 | 处理 |
|---|---|
| 解析到昵称 | 正常显示昵称 / 等级 / 头衔 / 积分，头像用页面里的 `img` |
| 有侧边栏但**没有**用户块 | 服务端确实把你当游客了 → 清 `登录参数`、显示问候语、提示「登录已失效」 |
| 两边都没匹配上（模板又改版 / 这页没侧栏） | **保持登录态**，标题写「已登录，点此刷新」 |

另外：

- 自动刷新收敛成**每次进软件一次**（全局 `侧滑栏已刷新`），不再每次首页加载都多发一个请求；
- 启动时的自动刷新走静默模式（失败不弹提示），手动点标题刷新才提示；
- 侧边栏壁纸仍然按模板 cookie 取，取不到就跳过，**不影响登录状态**。

**验证**：拿真实页面快照（`参考/有人清楚这人为啥要删帖吗 - MT论坛`）用 lupa 跑解析，
得到昵称「割草机Mow」、等级「Lv.5」、头衔「大学生」、积分「2530」、头像 URL 全部正确；
再构造「游客页（无 `sidenv_user`）」和「模板全改」两种 HTML，判定分别是「登录失效」和「保持登录态」。

### 3.8 「@某人」点了没反应（原版 bug）

**现象**：帖子里点 `@XXX` 完全没反应，抓包里也看不到任何请求；切到电脑版点同一个 @ 却能正常跳到
`https://bbs.binmt.cc/space-uid-160767.html`。

**原因有两个，叠在一起**

1. **路由把它吞了**。`pages/tiezi/main.lua` 的 URL 拦截里有一行：

```lua
local 好友表=url:match'bbs%.binmt%.cc/space%-uid%-%d+%.html'
...
   elseif 好友表 then
    return true          -- 既不加载、也不提示，等于把点击吃掉了
```

   手机模板里「@某人」和楼层作者名都是 `space-uid-123.html` 这种地址，所以**根本不会发请求**
   —— 这也是抓包一条都没有的原因。
2. **有些 @ 连链接都不是**：模板里存在纯文本 `@名字` 和 `href="javascript:;"` 的死链，
   点了本来就不会有任何跳转。

**改法**

路由（`tiezi` 与 `zhuye` 各一处）：

```lua
   elseif 好友表 then
    local uid=url:match('space%-uid%-(%d+)%.html')
    if uid then
      进子页面("yonghu",{"https://bbs.binmt.cc/home.php?mod=space&uid="..uid.."&do=profile&mobile=2"})
    end
    return true
   elseif 用户名页 then                      -- home.php?mod=space&username=xxx
    进子页面("yonghu",{url})
    return true
```

兜底（`tiezi_plus.lua` 注入脚本新增一段接管点击）：

- 点到 `javascript:` / `#` 开头的 `@名字` 链接 → `alert('__MLITE_USER__||名字')`；
- 点到**纯文本**里的 `@名字` → `document.caretRangeFromPoint(x, y)` 取点到的字符，
  往前找 `@`、往后取 2~24 个用户名允许的字符；`@` 前面紧挨字母/数字（`a@b.com` 这种邮箱）不触发；
- 原生收到 `__MLITE_USER__|uid|名字` 就打开用户页：有 uid 用 uid，没有就用
  `home.php?mod=space&username=名字`（Discuz 的 space 模块会自己解析成 uid）。

**验证**：node 桩测试 6 个用例——正常 @、点在 @ 前空格、邮箱、帖子外、`javascript:` 死链、普通链接，
结果分别是「打开 AI审核员」「不动作」「不动作」「不动作」「打开 割草机Mow」「放行」，全部符合预期；
`tiezi` / `zhuye` 的所有事件处理器再用 lupa 逐块编译，无语法错误。

## 6. 构建与校验（复用方法）

### 6.1 打包 `.fap`

`_x/build_fap.py`：把 `_x/fap` 目录按原条目顺序压回 `Mt论坛Lite重制版_1.7.fap`（文件名沿用 1.7，仅内容更新）。
校验：`zipfile.testzip()` + 与工作副本逐文件 MD5 比对。

### 6.2 打包 APK（不用 aapt/apktool）

原 APK 的 `assets/` 与 fap 解包结果完全一致，所以直接改包：

1. **改版本名**：`AndroidManifest.xml` 是二进制 XML，versionName 在字符串池里。重建字符串池把 `1.7` → `1.7.5`，再按 chunk 序列重排，校验头部 size 与 `END_DOCUMENT`。
2. **换资源**：替换 `assets/` 下 6 个 lua（`libs/gongyong`、`libs/tiezi_plus`、`libs/pm_plus`、`pages/tiezi/main`、`pages/shezhi/main`、`pages/yonghu/main`），同步 `assets/app.json` 的 versionName。新增的 `pm_plus.lua` 要作为新条目插在 `gongyong.lua` 之后。
3. **重打包**：手动构造 zip，保留原条目顺序与压缩方式；`resources.arsc` 保持 **STORED** 且数据区 **4 字节对齐**（注意：`ZipInfo.header_offset` 是本地头偏移，数据偏移 = `header+30+namelen+extralen`）。
4. **签名**：`keytool` 生成 PKCS12 → `apksig` 库签 V1+V2+V3，`setAlignmentPreserved(true)`。

工具：本仓库 `tools/` 下 `build_fap.py`（回 fap）、`build_apk.py`（改包）、`Sign.java`（签名）、`Verify.java`（验签）、`check_apk.py`（读版本/校验）、`apply_patches.py`（把补丁套到别的版本）。签名用的 keystore 需自己生成，见 `tools/README.md`。

### 6.3 每次必查

- `versionName=1.7.5`、`versionCode=7`
- 验签 `verified=true V1/V2/V3=true`、无 error/warning
- 4 个 lua 与 `_x/fap` 的 MD5 一致
- `resources.arsc` 数据偏移 `%4==0`
- 与旧 APK 逐条目 diff：除 manifest / app.json / 4 个 lua 外应全部字节一致

### 6.4 测试方法（无真机时）

- 注入的 JS 单独抽出来，`node --check` 过语法；
- 用 **jsdom** 构造页面跑逻辑（真实页面快照 `sample_thread.html` 来自用户保存的 MHTML）；
- 关键模拟：`documentElement.scrollTop` 强制返回 0（复现 WebView 行为）、`getBoundingClientRect` 按楼层索引算、`fetch` 按页码返回不同 HTML；
- **注意**：jsdom 里 `document.write()` 会额外触发一次 iframe `load`，数 onload 次数的逻辑会失真，测试中改用 `contentDocument.body.innerHTML = ...`。
- Lua 侧装 `lupa` 直接跑真 Lua 5.3 编译检查；中文标识符 LuaJIT 不认，做法是**把非 ASCII 字节替换成 `x`** 后再 `compile()`（不动引号/括号结构，仍能查出语法错）。
- 注入的 JS 也能用 node 跑：`node --check` 过语法，再用**手写的最小 DOM 桩**（`document/window/alert/XHR/DOMParser/sessionStorage`）跑一遍「到点自动发 → 收到 ok → 恢复草稿 → 替换列表」整条链路。

## 7. 已知限制

1. **选择器依赖 comiis 模板**：`.comiis_postli / .comiis_postlist / .comiis_message_table / .comiis_quote / .comiis_page / #dumppage / #select_a / #needmessage`。论坛改版或换模板需要先存一份网页快照重新核对。
2. **签名变了**：与原版签名不同，且 versionCode 仍为 7 → **覆盖安装必失败，需先卸载旧版**（会清掉登录状态、收藏、历史）。
3. **版本名 1.7.5 > 服务器 1.7**：软件内"检测更新"会提示发现新版本，属正常，忽略即可。
4. **未登录不弹窗**：未登录时页面显示"登录后查看"而非回复链接，识别不到（也回复不了），这是有意为之。
5. 长度阈值 10 字、纯字母数字符号规则是**用户明确要求**的，改小/删掉即可恢复更激进的屏蔽。
6. **倒计时卡片只在「个人中心」页面里显示**（私信列表/会话都在这个页面）。切到帖子页、板块页时卡片不显示；
   排队状态存在本地，回到私信页会重新画出来，自动发送也仍按原定时间走。
7. **服务端到底限制多久，代码是不知道的**：用的是设置里的固定秒数。设短了会被拒（弹窗提示、可手动重发），
   设长了只是白等。目前现场经验值是 15~16 秒，论坛改规则就调设置，不用改代码。
8. 发送后自动刷新列表依赖 `#comiis_pm_list` 这个容器。换模板导致找不到它时会退化成**整页重载**（草稿会保留）。
