# 移植到其它版本 · 操作指南

> 目标：把「回复可见自动回复 / 评论屏蔽 / 自动上下页重写」搬到 Mt论坛Lite 的**其它版本**（如 1.6、1.8 或别人改的版本）。
> 核心思路：**新模块独立，原生层只做接线**，所以大多数情况是"拷一个文件 + 改三处 + 加设置项"。

---

## 0. 先做体检（决定能不能直接照搬）

| 检查项 | 怎么查 | 不满足怎么办 |
|---|---|---|
| 是 Fusion App 工程？ | `.fap` 解包后有 `app.json`、`pages/`、`libs/` | 不是的话这套 Lua 接法不适用，只能取 JS 部分 |
| 有 `libs/gongyong.lua` 且含 `简易设置功能布局 / AlertDialog / print2 / 获取应用数据` | 全局搜函数名 | 缺哪个就补对应的原生实现，或改用该版本自己的弹窗/存储封装 |
| 帖子页是 `pages/tiezi/main.lua` 且用 `加载Js()` 注入 | 搜 `加载Js` / `单页文件上传影视解决` | 换成该版本的注入 API，注入时机保持"页面加载完成回调里" |
| 论坛是 comiis 模板 | 网页里能搜到 `comiis_postli`、`comiis_page` | 不是的话，第 4 节"选择器对照表"要整表重做 |
| 是否已有 `automatic_page_down()` | 搜这个名字 | 有冲突时决定保留谁：新模块更稳，建议注释旧调用 |

---

## 1. 解包与备份

```bash
mkdir -p _x/fap && cd _x/fap && unzip -o "../../你的版本.fap"
mkdir -p _原始备份 && cp 你的版本.fap 你的版本.apk _原始备份/
```

> 备份一定要在动手前做。后续打包脚本会覆盖同名 fap。

---

## 2. 拷入新模块

把本仓库 `src/fap/libs/tiezi_plus.lua`、`src/fap/libs/pm_plus.lua` 复制到目标工程 `libs/`。

两者都不依赖第三方库，只依赖全局函数：
`获取应用数据 / 存储应用数据 / 加载Js / AlertDialog / cjson / print / print2 / 横竖屏布局参数`。
（`刷新设置列表()` 里用到该版本设置页的 `listView` 变量名，若变量名不同需改。）

---

## 3. 改四处接线

### 3.1 `libs/gongyong.lua`

在文件靠前、其它 `if !获取应用数据(...)` 初始化附近，追加：

```lua
if !获取应用数据("回复可见自动回复") then 存储应用数据("回复可见自动回复","true") end
if !获取应用数据("自动回复内容")     then 存储应用数据("自动回复内容","看看隐藏") end
if !获取应用数据("评论屏蔽")         then 存储应用数据("评论屏蔽","true") end
if !获取应用数据("并行加载页数")     then 存储应用数据("并行加载页数","2") end
```

再加上「内置屏蔽词表 + 预置迁移」整段（见本仓库 `src/fap/libs/gongyong.lua` L107–146），**整段照抄即可**，只需注意：
`内置屏蔽词版本()` 起始值随便取，但**以后每次改词表都要 +1**，否则老用户拿不到新词。

### 3.2 `pages/tiezi/main.lua`

1. 顶部 `import "tiezi_plus"`（放在其它 `import` 之后）。
2. 找到"页面加载完成"的回调（本项目是 `单页文件上传影视解决(...)` 的标题/进度回调附近，搜 `自动上下页` 或 `加载Js`），在末尾加：

```lua
local 注入成功,注入错误=pcall(注入帖子增强)
if not 注入成功 then print("增强脚本注入失败："..tostring(注入错误)) end
```

3. 若该版本原本调用了 `automatic_page_down()`，注释掉（新模块接管），避免两套翻页抢 DOM：

```lua
-- if 获取应用数据("自动上下页")=="true" then 加载Js([[automatic_page_down();]]) end
```

4. 网页消息回调里加 `__MLITE_*` 分支（见本仓库 `src/fap/pages/tiezi/main.lua` L335–365），重点是最后那条兜底：

```lua
elseif message:sub(1,8)=="__MLITE_" then
  return true      -- 内部消息一律吞掉
```

> 没有兜底的话，`__MLITE_REPLY_SUBMITTED__` 之类会被当普通文本弹窗。

### 3.3 `pages/shezhi/main.lua`

1. 在「Js」分组列表里插入 5 项（`源码/pages/shezhi/main.lua` L33–38）。
2. 在 `switch(title)` 里加对应分支（L366–420）。

⚠️ **最容易翻车的点**：`简易设置功能布局()` 的开关状态是**以 `subtitle` 文本作为存储键**的。

```lua
{ __type = 5, subtitle = "评论屏蔽", status = { Checked = 获取应用数据("评论屏蔽") == "true" } }
--                 ^^^^^^^^^^ 这个字符串就是存储键，必须和 获取应用数据("...") 完全一致
```

如果目标版本是"用 id 或索引当键"的另一套布局函数，就要改成它自己的写法——**先读它的实现再抄**。

### 3.4 `pages/yonghu/main.lua`（私信页）

1. 顶部 `import "pm_plus"`。
2. **页面加载结束**回调里注入（只在私信页）：

```lua
local 私信相关 = url and (url:match('mod=space&do=pm') or url:match('mod=spacecp&ac=pm'))
if 私信相关 then
  local 注入成功,注入错误=pcall(注入私信增强)
  if not 注入成功 then print("私信增强注入失败："..tostring(注入错误)) end
end
```

3. 在 `单页文件上传影视解决(...)` 的**第 5 个参数**（网页提示框）里拦内部消息：

```lua
单页文件上传影视解决(nil, nil,
function(super,view,title) … end,      -- 3 标题
nil,                                   -- 4 图标
function(a,view,url,message,result)    -- 5 网页提示框 ★
  if 私信处理消息(message) then
    result.cancel()
    return true
  end
end,
nil, nil, nil,                         -- 6 确认框 / 7 输入框 / 8 控制台
function(superCall,view,progress) … end, -- 9 进度
nil, nil, nil, nil)
```

⚠️ 四个坑：
- 网页提示框在 **`单页文件上传影视解决`** 里，**不是** `页面事件处理`。插错了 `alert()` 就等于没拦住，
  `__MLITE_PM_*` 会变成普通弹窗弹给用户。
- 私信页 URL 必须同时认 `mod=space&do=pm`（会话页）和 `mod=spacecp&ac=pm`（POST 目标）。
- `result.cancel()` 只对内部消息调用，别把网站自己的 alert 也吞了。
- **不要只依赖 alert 通道**。`pm_plus` 里还开了一条备份通道：JS 把同一条消息塞进 `window.__mlitePmOut`，
  原生每 700ms `加载Js(...回调)` 取回。移植时这条要一起搬（`私信开始轮询()` + `私信延时()`），
  否则一旦 alert 回调没接上，整个模块就"毫无反应"，很难查。
- 界面**不要用原生悬浮窗**。`activity.getWindow().getDecorView().addView()` 在部分 Fusion App 工程里
  静默不显示（本项目实测一次都没出现过）。改成网页内 `position:fixed` 卡片，能稳定显示；
  代价是切到别的页面会消失（状态存原生，回来重画）。

如果目标版本把私信放在别的页面（不是 `yonghu`），先搜 `do=pm` 找到那个页面的 main.lua，把上面两段搬过去。

### 3.5 电脑版网页（可选）

1. `libs/gongyong.lua` 里加三个函数：`电脑版网址()` / `手机版网址()` / `打开电脑版网页()`（见 `修改总结.md` 3.5）。
   它们依赖现成的 `liulanyepc`（PC 浏览页）和 `拓展功能 → 电脑UA`，不需要新页面。
2. 每个带三个点菜单的页面，在 `右上角按钮(0,0).onClick` 里加一行 `主菜单.add("电脑版网页")`（放在「退出页面」前），
   并在 `switch item.title` 里加 `case "电脑版网页" 打开电脑版网页()`。
3. `liulanyepc` / `liulanyeqp` 里给 WebSettings 打开 `setUseWideViewPort(true)` + `setLoadWithOverviewMode(true)`，
   否则桌面模板只显示左半边。
4. `libs/gongyong.lua` 再加三个工具函数：`同一网页()`（比较 URL，忽略 `mobile` 与锚点）、
   `用手机版页面打开()`（URL → `tiezi`/`bankuai`/`yonghu`/`qiandao`/`denglu` 的分发）、
   `重置手机版Cookie()`（把名字含 `mobile` 的 cookie 过期）。
5. `liulanyepc` / `liulanyeqp` 里记一个 `入口网址 = tostring(传递数据 or "")`，并写 `回到手机版()`：
   - 当前地址与入口**同一页** → `退子页面()`（回到原来那个页面，**不重新加载，导航栏还在**）；
   - 翻到别的页面了 → `用手机版页面打开(手机版网址(当前))`，接不了才 `进子页面("liulanye", …)`。
   菜单里的「手机模式」直接调它。
   ⚠️ 不要用「重载成手机 UA」的方式切回手机版：会重新加载一遍，而且出来的是浏览页，**没有首页的导航栏**。
   ⚠️ 也不要用「跳到 `liulanye` 页」：依赖另一个页面的 UA 初始化，且论坛可能把电脑版记在 cookie 里。
6. `打开电脑版网页()` 里先纠一次地址：`view=hot`（首页）和 `forumlist=1`（社区）都改成 `/forum.php`，
   否则进的是导读页 / 版块列表页；`zhuye` 页面再按 `this.uiManager.viewPager.getCurrentItem()` 兜一层。

> ⚠️ 出包时记得把**改过的页面**登记到 `build_apk.py` 的 `repl` 白名单里，否则 APK 里还是旧文件。

## 4. 选择器对照表（换模板时逐项核对）

| 用途 | 当前选择器 | 说明 |
|---|---|---|
| 楼层列表容器 | `.comiis_postlist` | 追加新楼层也插在这里 |
| 单个楼层 | `.comiis_postli[id^="pid"]` | 靠 `pid` 去重；`#post_new` 是回复框要排除 |
| 楼层正文 | `.comiis_message_table` → `.comiis_message` → `.message` → `.t_f` → `[id^="postmessage_"]` | 取**最内层**，否则会带上引用块 |
| 楼主帖标记 | `.comiis_postli_topv1` / `.comiis_pltit` | 用于"楼主帖不屏蔽" |
| 引用块 | `.comiis_quote` | 区分"回复别人"与"回复可见提示" |
| 回复可见提示 | `.comiis_quote / .showhide / [class*="showhide"] / .comiis_hidebox` + 块内 `a[href*="action=reply"]` | 有回复链接才算 |
| 分页区 | `.comiis_page` / `.comiis_multi_box` | 里面的"下一页" `<a>` |
| 页码下拉 | `#dumppage`（`opacity:0`）、`#select_a`（可见文本） | 文本节点才是用户看到的页码 |
| 快捷回复表单 | `#fastpostform`、`#needmessage`、`#fastpostsubmit`、`window.fastpostvalidate` | 发回复用 |
| 私信发送表单 | `#pmform` + `input#needmessage[name=message]`（是 **input** 不是 textarea）、`input#pmsubmit[type=button][comiis=handle]` | 填值/自动发送；多级兜底见 `box()/btn()` |
| 私信发送接口 | `form[action*="ac=pm"]` 且 `action*="op=send"`，POST 后回 JSON（`ok` / `message`） | XHR hook 靠这两个串判断是不是私信；**成功响应体抓不到也不影响**，代码按「非太快即成功」容错 |
| 私信消息列表 | `#comiis_pm_list`（内含 `#comiis_pm_list_new`） | 发送后自动刷新就是重新 GET 当前页、替换这个容器 |
| 倒计时卡片 | `#mlite-pm-card`（自己创建的，`position:fixed`） | 不需要在模板里找，挂在 `document.body` 上 |
| 快速回复框 | `#fastpostform` → `textarea#needmessage` | 底部那排快捷菜单靠它的 `onclick` alert 显示 |
| 楼层「回复」弹层 | `#ntcmsg_popmenu` → `#postforms` → `textarea#needmessage`（**与上面同 id**） | 弹层里的框要单独认，见 `修改总结.md` 3.6 |
| 侧边栏用户块 | `.comiis_sidenv_box` → `.sidenv_user` → `.user_tit` / `.user_lev` / `p.f13` | 昵称/等级/头衔/积分都从这几个 class 取，见 `修改总结.md` 3.7 |
| 用户页地址 | `space-uid-123.html` / `home.php?mod=space&uid=123&do=profile` / `home.php?mod=space&username=名字` | 三种都要路由到 `yonghu` 页面，**不要 `return true` 吞掉**（见 3.8） |
| 限速提示 | `#frl-notice` / `#frl-message`（插件画的，4 秒自消） | 只作兜底，主路径读 JSON |

**核对方法**：让用户把目标版本的帖子页"另存为"，从 MHTML 里提取 HTML，用 jsdom 跑一遍 `work_inspect*.js` 那类脚本，打印实际 class / id 再定选择器。**不要凭猜测**。

## 5. 打包与校验

```bash
# 0) 准备：把原版 Mt论坛Lite重制版_1.7.apk 放到 base/

# 1) 回包 fap
python tools/build_fap.py

# 2) 回包 APK（改 versionName → 换 assets → 重签）
python tools/build_apk.py
javac -cp apksig.jar tools/Sign.java            # 第一次需要编译
java -cp "apksig.jar:tools" Sign build/unsigned.apk build/xxx.apk mykey.p12 你的密码 别名 你的密码
java -cp "apksig.jar:tools" Verify build/xxx.apk
```

校验清单见 `docs/修改总结.md` 第 6.3 节。

> **签名用自己的 keystore**（见 `tools/README.md`：`keytool -genkeypair` 生成一个即可）。
> 换签名后**不能覆盖安装**，必须先卸载原版。

## 6. 移植后必须跑的用例

1. **普通帖不弹窗**（无回复可见）→ 不弹。
2. **回复可见帖** → 弹一次，确定后自动回复并刷新，隐藏内容出现；再进同帖不重复弹。
3. **短帖（1 页 3 楼）** → 底部无任何"正在加载/加载失败"，`fetch` 0 次。
4. **长帖（≥10 页）** → 持续下拉能一路拼到底，底部页码跟随变化，末页提示「当前已是最后一页」。
5. **屏蔽**：水贴短句消失且下方楼层上移；楼主帖、回复别人的楼层、>10 字长评论保留。
6. **两个开关分别关掉** → 对应功能立刻不生效（重进帖子）。
> 私信相关的用例请在**还有配额**的时候测（我用完配额后只能靠桩测试，见 6.4）。

7. **注入生效**：打开任一会话，输入框上方**不应**出现任何提示（早期版本会弹一次「私信自动重发已启用」，已去掉）。
   想确认注入是否跑起来：在控制台执行 `__mlitePm.state()`，能返回对象即正常。
8. **计时与显示**：发一条私信 → 成功 → 卡片出现「距可再次发送 16 秒」，1 秒 1 跳；
   **第 3 秒**再点发送 → 卡片变「① 13 秒后自动发送 · 内容…」，底部 toast 提示还剩 13 秒。
9. **自动补发**：等倒计时归零 → 消息自动发出，卡片消失，会话里**立刻出现**刚发的那条（不需要手动刷新）。
10. **草稿不被吃**：先在输入框打一句不发的草稿 → 让队列到点自动发 → 发完输入框里仍是那句草稿。
11. **被拒路径**：把「限速等待秒数」临时调成 10 秒 → 自动补发大概率被服务端拒 → 应弹一次说明框、
    卡片变「被拒 · 点此重发」，**不会**自动再排一轮。
12. **取消/重发**：卡片上点「取消」→ 该行消失且不再发；点「重发」→ 立刻再发一次。
13. **跨页**：切到帖子页卡片消失（正常），回私信页重新出现且秒数连续；`__mlitePm.state()` 可随时查看 `{win,last,left,my,q}`。
14. **电脑版网页**：在帖子页 → 右上角 ⋮ →「电脑版网页」→ 打开的是桌面版帖子页（不是缩成一团的触屏版），
    返回键回到原页面；在个人中心页试一次（地址带 `mobile=2`，最容易被漏掉的一类）。
15. **切回手机版**：电脑版页里点「手机模式」→ **直接回到原来那个页面**（没有重新加载、导航栏还在、返回键不再多一层）；
    在电脑版里点开另一篇帖子后再点「手机模式」→ 打开的是 App 的帖子页（手机版），而不是浏览页。
16. **首页进电脑版**：首页 → ⋮ →「电脑版网页」→ 应该是 `https://bbs.binmt.cc/forum.php`（论坛首页），
    不是 `forum.php?mod=guide&view=hot` 的导读页；社区栏同理进论坛首页；导读栏则进电脑版导读页。
17. **弹层快捷菜单**：点某楼右下角「回复」→ 小窗弹出时底部出现快捷菜单 → 点「加粗」，
    文字应当插到**小窗的输入框**（不是下面那个快速回复框）；取消小窗 → 菜单栏收起；
    先打开底部快速回复再点某楼回复、取消，菜单栏应当**留着**（因为底部框还开着）。
18. **侧边栏登录状态**：登录后重进软件 → 左侧栏直接显示昵称 / Lv / 头衔 / 积分，**不应**出现「请登录」或「登录失效」；
    点标题若还能刷新到昵称就说明解析路径正常。退出登录后重进 → 显示「早上好!请登录」这类问候语。
19. **@某人**：帖子正文里点 `@某某` → 应打开该用户的用户页（不是没反应）。
    正常链接、纯文本、`javascript:;` 三种形态都要试；点邮箱里的 @（`a@b.com`）不应误跳。

无真机时用 jsdom 跑；有真机时直接看底部提示文案判断卡在哪条路径：
「正在加载第 N 页…」= 请求中/被拦；「点此重试」= 连续 2 页被风控；「当前已是最后一页」= 正常结束。

## 7. 常见改造需求（直接改哪里）

| 需求 | 改动位置 |
|---|---|
| 回复内容默认值 | `gongyong.lua` 的 `存储应用数据("自动回复内容","看看隐藏")` |
| 取消"超过 N 字不屏蔽" | 注入脚本 `blockReason()` 里删掉 `if (t.length > 10) return '';` |
| 连长评论也按词屏蔽 | 同上；注意可能误伤正常长回复 |
| 允许屏蔽楼主帖 | `applyBlock()` 里删掉 `if (isOP(f)) continue;` |
